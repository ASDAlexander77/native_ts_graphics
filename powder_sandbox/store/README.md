# Powder Sandbox on Google Play

What's here and how a release is made.

| Path | What it is |
|---|---|
| `../android/` | The Gradle module the store build is packaged by (`tools/package_apk.py --gradle`): the manifest, `PowderActivity` (the game's NativeActivity) and the support ads (`SupportAds`, `SupportSchedule`), with their unit tests in `test/`. |
| `../android/res/` | The launcher icon: an adaptive icon (background, foreground and a monochrome layer for themed icons), as vector drawables. Generated by `make_store_art.py`. |
| `listing/en-US/title.txt`, `short_description.txt`, `full_description.txt` | The store listing's text (30, 80 and 4000 characters at most). |
| `listing/en-US/changelogs/<versionCode>.txt` | Each release's notes ("What's new"). |
| `listing/en-US/images/icon.png` | The store icon, 512 x 512. |
| `listing/en-US/images/featureGraphic.png` | The feature graphic, 1024 x 500. |
| `listing/en-US/images/phoneScreenshots/` | Screenshots: frames of the test scenes (`-testOutput`). |
| `PRIVACY.md` | The privacy policy. Play needs it at a public URL (this file's GitHub page will do). |
| `make_store_art.py` | Draws the icon (both forms) and the feature graphic: run it again after changing the shapes. |

The folder follows fastlane's `metadata/android` layout, so `fastlane supply` can upload it as it is.

## The app

- Application ID `io.github.asdalexander77.powdersandbox` (permanent once uploaded), label
  "Powder Sandbox", category game.
- Target SDK 36 (Google Play's level for new apps since 31 August 2026), minimum SDK 29.
- Needs Vulkan 1.3 (`android.hardware.vulkan.version` 0x403000, required; NRI itself needs 1.2 with
  dynamic rendering and synchronization2, which 1.3 makes core): Play offers it only to
  devices that can run it. arm64-v8a and x86_64 (Chromebooks, emulators) in one bundle.
- Not debuggable, no backup. The system bars are hidden (a swipe shows them).
- Optional ads (Google AdMob, rewarded): after 10 minutes of play, then every 20, the app asks
  whether the player would watch an ad to support it; only a "Watch ad" shows one. Google's consent
  message (UMP) comes first where the law needs it. Not for children: ad content capped at Teen.
  AdMob adds the internet, network-state and advertising-ID permissions.
- Packaged by Gradle (it fetches Gradle, the Android Gradle plugin and the AdMob libraries on the
  first build, into the build folder and `~/.gradle`).

## 1. A release keystore (once)

Make it yourself and keep it, with its passwords, somewhere safe and backed up: every update must
be signed with the same key. (With Play App Signing, this is the *upload* key: Google holds the
app's signing key, and a lost upload key can be reset through Play support.)

```bat
"C:\Android\jdk\jdk-21.0.12.1+1\bin\keytool" -genkeypair -keystore D:\keys\powder-sandbox-upload.jks -storetype PKCS12 -alias upload -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=Your Name"
```

keytool asks for the password. Then configure the two Android builds (once):
`../config_release_apk_for_deployment.bat` does it, with the keystore at I:\keys (edit it for
another place):

```bat
cmake --preset android-x86_64
cmake --preset android-arm64 -DANDROID_RELEASE_KEYSTORE=D:\keys\powder-sandbox-upload.jks -DANDROID_RELEASE_MERGE_BUILDS=<repository>/build-android-x86_64
```

The arm64 build makes the release; `ANDROID_RELEASE_MERGE_BUILDS` has it package the x86_64 build's
libraries too.

## 2. Build

The passwords come from environment variables, never from the command line or a file in the repo.
So do the real AdMob IDs (AdMob > Apps > the app's ID, `ca-app-pub-...~...`, and its rewarded ad
unit's, `ca-app-pub-.../...`): without them the release shows Google's test ads, and the build says
so (`package_apk: WARNING: ... TEST ads`). Never upload such a build.
`../build_release_apk_for_deployment.bat` builds the x86_64 libraries first, then the release:

```bat
set ANDROID_RELEASE_STORE_PASSWORD=...
set ANDROID_RELEASE_KEY_PASSWORD=...
set POWDER_ADMOB_APP_ID=ca-app-pub-...~...
set POWDER_ADMOB_REWARDED_ID=ca-app-pub-.../...
cmake --build --preset android-x86_64 --target powder_sandbox_nri_apk
cmake --build --preset android-arm64 --target powder_sandbox_nri_release
```

It writes to `build-android-arm64/bin/`:

- `powder_sandbox_nri-release.aab`: the bundle to upload to Google Play (both ABIs, one version
  code: Play gives each device its ABI's split);
- `powder_sandbox_nri-release.apk`: the same build as an APK with both ABIs, to install and check
  first (`../install_apk.bat release`) or for other stores;
- `powder_sandbox_nri-native-debug-symbols.zip`: both ABIs' libraries; upload it with the bundle (App bundle explorer >
  Downloads > Native debug symbols), so crash reports show function names.

For each next release, raise `VERSION_CODE` (and `VERSION_NAME`) in `../powder_sandbox.cmake` and
add `listing/en-US/changelogs/<VERSION_CODE>.txt`.

## 3. Play Console (by hand)

1. Create the app: name "Powder Sandbox", game, free.
2. Store listing: paste the text from `listing/en-US/`, upload the icon, the feature graphic and the
   screenshots; category Simulation (or Puzzle).
3. App content: privacy policy URL (`PRIVACY.md`'s page); ads: **contains ads**; target
   audience: **13 and over** (not children, so not in the Families program); content rating
   questionnaire (no violence beyond things burning and exploding, no user content shared, no
   purchases). Data safety, from AdMob's disclosure guide
   (https://developers.google.com/admob/android/privacy/play-data-disclosure): data is collected
   and shared, encrypted in transit, by the AdMob SDK: **Device or other IDs** (advertising ID),
   **App activity** (app interactions), **App info and performance** (crash logs, diagnostics) and
   approximate **Location** (from the IP address), for Advertising or marketing, Analytics and Fraud
   prevention. Check the guide's current list when filling the form in.
4. AdMob (once): add the app (Android, linked to its Play listing), make a **Rewarded** ad unit,
   and put the two IDs in the environment variables above. Publish
   `https://<your developer website>/app-ads.txt` with the line AdMob shows for the account, and
   set that website in the store listing. In AdMob > Privacy & messaging, create the GDPR consent
   message: the app shows it through UMP, which has nothing to show without it.
5. Testing: Google requires a closed test with testers before production for new personal
   accounts. Upload the .aab to a testing track first.

A follow-up worth doing before wide release: a "Privacy options" entry in the game, which GDPR
consent needs so players can change their consent later (UMP's `showPrivacyOptionsForm`); the game
has no settings screen reachable from Java yet.

## Trying the ads (debug)

`cmake --build --preset android-x86_64 --target powder_sandbox_nri_ads` (or android-arm64) makes
`bin/powder_sandbox_nri-ads-debug.apk`: the same app with Google's test ads, debug-signed, as
`io.github.asdalexander77.powdersandbox.debug` (beside a Play install). Started with the extra
`ads_fast`, it asks after 10 s of play, then every 20 s:

```bat
adb install -r build-android-x86_64\bin\powder_sandbox_nri-ads-debug.apk
adb shell am start -n io.github.asdalexander77.powdersandbox.debug/io.github.asdalexander77.powdersandbox.PowderActivity --ez ads_fast true
```

The on-emulator check needs an image with Google Play services, and on this machine the emulator
with `-gpu swiftshader_indirect` (its host-GPU mode crashed on the game's Vulkan instance).
